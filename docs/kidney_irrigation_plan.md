# 肾脏腔室注排水形变与展示视频实施计划

日期：2026-10-10。依据：当前仓库静态检查、OBJ 网格统计及 Godot 官方文档。本文是实施计划，尚未实现形变或录制视频。

## 1. 目标与第一版边界

在现有 Godot 内镜仿真上，展示肾脏集合系统腔室在“参考状态 → 注水扩张 → 维持 → 排水回缩 → 恢复参考状态”过程中的连续几何变化，交付可交互演示场景、可重复播放的演示流程和一段约 60 秒的展示视频。

第一版采用**预计算局部位移场／同拓扑形态插值 + 注排水状态控制**。重点是腔壁实际移动、局部变化合理、前后对比清晰、可稳定录制。整个肾脏统一缩放不能作为最终方案。

目前没有已确认的注水前后配对模型、实验压力—容积曲线或材料参数。因此，第一版属于参数化形变演示，不能把当前 CT 重建形态认定为真实“未注水”状态，也不能把演示形变量宣称为经过验证的生理响应。视频使用“参考状态”“注水扩张示意”等表述。

第一版不要求自由液面、水流粒子、完整流固耦合、器械接触导致的软组织形变或动态路径重规划。这些可以独立升级，不应成为视频交付的前置条件。

## 3. 技术路线

### 3.1 先确认“哪一层表面在扩张”

1. 分别加载腔体和组织，统一坐标、旋转、单位，检查与现有路径的配准。
2. 用剖切和固定内镜视角检查组织是否包含当前可见内腔表面，核对腔体表面是否可直接作为腔壁渲染面。
3. 检查法线、自交、闭合性、局部网格质量与两层表面间距离；确认腔体封闭端的含义及入口位置。
4. 建立肾盂、肾盏／分支、入口过渡和固定区的区域标注。首版可人工标注少量控制区，再平滑生成每顶点权重；若存在可复用的完整骨架，后续辅助自动标注。

**决策门槛：**只有确认参考腔壁、入口固定区和组织映射后，才进入形变制作。若组织内腔与腔体不一致，先修复映射或选择独立腔体展示，不能叠放两层近似表面造成穿插和闪烁。

### 3.2 预计算局部形变，运行时只控制幅度

为每个区域构造平滑位移场：腔壁沿局部横截面向外移动，固定区位移为零，过渡区连续衰减。不能只围绕全肾包围盒中心作径向缩放；分叉附近也不能直接使用最近单一中心线点，否则容易发生方向跳变。

建议第一版制作三个保持拓扑和顶点对应关系的状态：

- `reference`：原始参考形态。
- `mid`：中等扩张形态。
- `expanded`：最大演示扩张形态。

预处理阶段可用控制笼、平滑控制场或区域约束编辑生成目标形态；优先复用现有网格，不以 Blender 为必需依赖。运行时用 Godot ArrayMesh 的 Blend Shape 或同拓扑顶点插值实现连续变化。若采用多目标，使用分段插值或明确的权重约束，避免同时叠加目标导致过度扩张。

形变关系可写为：

`x_i(t) = x_i,reference + D_i(u(t))`

其中 `u ∈ [0,1]` 是演示充盈参数，`D_i` 是带区域与固定边界约束的位移。每帧从参考形态求值，不能在上一帧位置上累加位移，以免产生漂移。

组织表面通过共同控制场或预计算空间映射跟随腔体变化，约束组织外表面位移和局部壁厚。不是要求外表面完全不动，也不是默认内外壁等幅移动；具体关系通过几何检查与演示目的确定。

同时处理法线／必要时切线、形变后的包围盒和材质采样。当前三平面材质基于世界坐标，需检查形变过程中是否出现明显纹理滑动；必要时改用参考坐标采样。

### 3.3 注排水状态控制

第一版状态机：

`参考 → 注水 → 保持 → 排水 → 恢复`

提供注水、停止／保持、排水、重置和强度调节，并支持自动演示时间线。注水使目标充盈度上升，排水使目标充盈度下降，使用平滑响应避免跳变。界面优先显示阶段和归一化充盈度，不显示未经标定的压力或真实注水量。

停止进水后的行为必须由出口条件决定：第一版“保持”明确表示停止进出水；“排水”表示开启排出过程。不能把“停止注水”无条件等同于“自动回缩”。

若后续需要输入流量、输出压力和体积，再单独引入示意性集中参数模型：

`dV/dt = Q_in - Q_out`

`P = f(V)`

`u_target = g(V)`

必须区分输入流量、累计注入量、净滞留量和腔体几何体积；泄漏／出口阻力、顺应性和松弛参数需要定义并标定。此时还要用实际形变网格计算出的容积反查 `g(V)`，使界面数据与几何变化一致。

### 3.4 渲染、碰撞和内镜分阶段接入

**首个可录制版本：**固定内镜观察位姿，关闭自动巡航和输入移动，展示真实网格形变；检查整个形变范围内相机与腔壁的距离。此版本不宣称支持形变中的器械接触。

**交互完善版本：**增加低面数腔壁碰撞代理，由同一 `u(t)`／位移场驱动，按实测性能采用约 5–10 Hz 更新作为初始尝试。在安全的物理更新时机替换碰撞数据；评估插值、碰撞滞后和相机被回缩腔壁包住的情况。更新频率不是固定验收结论，要由误差和性能共同决定。

禁止把 GPU／Blend Shape 可见变化当作碰撞已经同步。腔内碰撞代理还要明确法线、背面碰撞与碰撞层设置。

若视频增加内镜巡航，优先在固定充盈阶段播放短路径，并核对每个展示充盈状态下的最小壁距。第一版不默认原来的静态优化路径适用于所有形态，也不把碰撞代理同步等同于完成路径重规划。

### 3.5 展示视角

- 外部主视图：不透明剖切或独立腔体视图，能看清肾盂和分支扩张。
- 内镜辅助视图：固定相机位姿、FOV 和主要光照，显示同一位置的腔壁前后变化。
- 最终对比：同视角的参考／扩张画面对照，必要时增加参考轮廓线。
- 画面文字：当前阶段、充盈参数、区域名称；只使用经过确认的单位与数值。

现有内镜视图使用 SubViewport，新增外部视图时需要明确共享 World3D 或使用同步的模型实例，避免外部相机看不到内镜所在世界。为两个视图分别设定可见层和灯光，保持镜头可比性。

## 4. 分阶段工作计划与验收

以下为一名熟悉 Godot 与网格处理的开发者、资产可用条件下的初步工作量估计；包含视频导出，不包含医学参数采集与验证。若发现网格需大规模修复，应在第一阶段后重估。

| 阶段 | 主要工作 | 产物与通过条件 | 预计工作量 |
| --- | --- | --- | --- |
| P0 基线与资产核对 | 运行原场景；确认实际引擎；核对模型／路径坐标和内腔表面；做短片录制试验 | 原场景截图、模型检查记录、可用的录制路径；明确形变表面和固定区 | 0.5–1 天 |
| P1 静态目标形态 | 区域标注、位移场、参考／中间／扩张形态、组织映射与法线处理 | 三态对比；固定区稳定，局部扩张清晰，无明显自交、翻面或壁厚失效 | 1–1.5 天 |
| P2 动态形变与控制 | Godot 形态插值；状态机；注水／保持／排水／重置；参数面板 | 一个完整往返循环可交互播放，无跳变、无累计漂移；参考状态可恢复 | 1 天 |
| P3 场景集成与验证 | 外部视图＋内镜视图；包围盒／材质处理；必要的碰撞代理与路径检查 | 固定镜头在全程安全；若启用移动，则碰撞与显示误差经检查；记录性能 | 1–1.5 天 |
| P4 自动演示与录制 | 自动时间线、镜头布局、字幕；预览修正；正式渲染与编码 | 约 60 秒、1920×1080、30 fps 的视频，前后对比清楚、可正常播放 | 0.5–1 天 |
| P5 交付整理 | 操作说明、参数说明、复现步骤和最终检查 | 可重放场景、源代码／配置、视频、前后截图、限制说明齐全 | 0.5 天 |

合计约 **5–6.5 个工作日**，排期建议预留 **5–7 个工作日**。P2 结束是首个动态原型里程碑；P4 结束是视频交付里程碑。第一轮只处理当前一套资产，避免同时承担多器官泛化。

## 6. 视频分镜与制作

建议约 60 秒，1920×1080，30 fps，成片为 MP4；留存 AVI 或 PNG 序列作为制作源。

| 时间 | 内容 |
| --- | --- |
| 0–5 秒 | 标题、参考状态、简短说明“参数化形变演示” |
| 5–15 秒 | 外部剖切主视图中缓慢注水，内镜辅助视图同步呈现 |
| 15–20 秒 | 保持扩张，突出肾盂和分支轮廓 |
| 20–30 秒 | 同一外部视角下排水回缩，镜头和光照保持稳定 |
| 30–35 秒 | 恢复参考状态，短暂停留 |
| 35–50 秒 | 固定内镜位置，完成一次更短的扩张—保持—回缩展示 |
| 50–60 秒 | 同视角参考／扩张并排对比，注明归一化充盈参数 |

先录制 5–10 秒低成本预览，检查腔壁是否可辨、字幕是否清晰、相机是否穿模以及视频能否播放，再导出正式版本。宽屏录制需要同时检查主窗口、SubViewport 尺寸与内镜辅助画面比例，不能只修改窗口宽高。

采用 Godot Movie Maker 的固定帧率离线录制，时间线按游戏时间／帧推进，不依赖真实时钟或临时键盘操作。按脚本正常退出，避免强制终止产生不完整的 AVI。MP4 可由可用的 FFmpeg 或视频编辑器编码。

实施完成后的命令形式示例如下；`godot` 需替换为实际可执行文件，演示脚本需先实现自动播放和正常退出：

```powershell
godot --path godot_sim --write-movie recordings/kidney_irrigation.avi --fixed-fps 30 --resolution 1920x1080 res://irrigation_demo.tscn
ffmpeg -i godot_sim/recordings/kidney_irrigation.avi -c:v libx264 -crf 18 -pix_fmt yuv420p -movflags +faststart -an godot_sim/recordings/kidney_irrigation_demo.mp4
```

该命令只是计划示例，当前尚未执行。正式录制前以实机引擎帮助信息核对参数。`-an` 对应无声展示片；如增加配音，另行保留或混入音轨。

## 7. 验收标准

1. **变化正确：**能看到腔室局部扩张和回缩；入口固定区稳定；模型没有整体漂移。比较采用相同相机位姿与 FOV。
2. **几何有效：**对 `u=0、0.25、0.5、0.75、1` 及自动循环采样检查翻面、自交、壁厚和分叉连续性。对于验证为封闭且方向一致的腔体，计算体积并检查随充盈度按设定增长；不能只比较包围盒尺寸。
3. **往返稳定：**连续播放至少三个循环，最后形态回到参考形态。首轮顶点恢复误差目标不大于 0.01 mm，固定区误差同量级；这是工程数值目标，不是生理精度声明。
4. **状态清楚：**注水、保持、排水、恢复行为可重复；暂停和重置不导致状态错乱；相同配置产生相同时间线。
5. **集成有效：**固定内镜在全程不穿模；若开放移动，补查代理与可见壁距离误差、回缩包围器械的处理和路径安全，不能仅凭画面宣称通过碰撞验证。
6. **性能可用：**在记录的目标设备上，交互演示争取达到 30 fps；测量形变、碰撞更新和双视图开销。离线录像达到 30 fps 播放并不能证明实时运行达到 30 fps。
7. **视频可交付：**时长约 60 秒、1080p、30 fps，完整可播放，无明显闪烁／黑帧；阶段和前后变化清楚。
8. **可复现：**交付模型／参数来源、运行和录制说明；未经标定的数据均标注为演示参数。

## 8. 风险、应对和后续升级

| 风险 | 应对 |
| --- | --- |
| 当前参考网格并非真实未注水形态 | 明确称为参考状态；有配对数据后再更新基准与目标形态 |
| 腔体与组织表面关系不清、无顶点对应 | P0 先配准与剖切；共同控制场／空间映射；禁止索引直接复制 |
| 分叉和狭窄部位扩张后穿插 | 区域权重平滑、限制位移、增加中间形态并检查全过程 |
| 高面数导致卡顿 | 预计算目标形态；运行时插值；碰撞使用独立低面数代理 |
| 半透明与景深触发已有渲染问题 | 首版用不透明剖切，先做短片预览验证 |
| 内镜移动掩盖形变，或静态路径失效 | 以固定镜头为主要证据；巡航仅在经检查的形态和短路径上增加 |
| UI 体积／压力与几何不一致 | 第一版只显示归一化参数；定量版本使用几何体积校准映射 |
| 开发机环境不完整 | 优先确认已有引擎和环境路径，按所选路线补充最小依赖 |

升级顺序：配对注水前后模型／实验测量 → 标定容积和充排水响应 → 压力—容积模型 → 有限元或其他组织力学求解与离线形态库 → 动态碰撞、器械接触和路径重规划 → 必要时流固耦合。

若任务验收本身要求“给定实际流量／压力，预测真实膨胀量”，需要把参数采集、物理建模和实验验证移入主线，另行排期；上述 5–7 天估计仅对应可控形变与视频演示版本。
